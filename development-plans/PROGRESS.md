## Update protocol (mandatory for every agent session)

1. **On session start:** read this file top to bottom. Resume from the first non-✅ phase. Never re-do ✅ work; never skip a 🟡 blocker without resolving it.
2. **On phase start:** set status 🔵 with date; copy that phase's *Acceptance criteria* checklist verbatim into the phase section below.
3. **During work:** append Session log entries (date, what was done, key commands/results). Record every deviation or decision in the Decisions log — a decision without a written rationale is a bug.
4. **On acceptance check:** tick each criterion only with one line of evidence (test name + count, command output summary, or e2e spec name). Unproven ticks are forbidden.
5. **On phase completion:** verify the Definition of Done ([01-architecture.md](01-architecture.md) §20), set ✅ with date, update the status table, commit.
6. **On blocker:** set 🟡, fill a Blockers entry (symptom, what was tried, smallest human decision needed), STOP work on that phase.
7. **Human review items:** add to the Human review queue; these do not block progress unless marked GATE.

### Phase 10 — Hardening & Release · 🟠 Awaiting human review (2026-08-02)

below; what remains needs a domain, an account, a card or a signature, and is

**Acceptance criteria** (copied verbatim from phase-10-hardening-release.md):

The zip bomb found a real gap and closed it: `convert.check_archive` reads the central directory *before* LibreOffice is handed the file. **Decisions** (also in the Decisions log):
- **A completed signature envelope outlives the account that sent it.** `SignRequest.owner` and `.document` became `SET_NULL`, and the sender is snapshotted as text at send. The counterparty signed a contract; deleting their evidence because the other party closed an account is the wrong answer, and the privacy policy now says exactly what is kept.
- **The audit chain is never rewritten, including by deletion.** Editing one row breaks every hash after it and destroys the thing being kept.
- **Zero retries in Playwright.** A test that passes on the second attempt is telling you something about the product, and a retry count is how that stops being heard.
- **Cross-browser is opt-in.** Three engines on every run triples a suite that drives real PDFs through a real worker; the failures we have actually hit are logic, not engine. The nightly run sets `BROWSERS=all`.

### Phase 9 — Ads & Abuse Controls · ✅ Complete (2026-08-02)

**Acceptance criteria** (copied verbatim from phase-09-ads-and-abuse-controls.md):
- [x] With `ADS_ENABLED=false` (default): zero ad code loaded, product fully functional — launchable state. → `/api/config/` answers `ads: {enabled: false}` and **nothing else** — no client id, no provider, no slot ids — so a build with the flag off has nothing to load even by mistake (`test_ads_and_abuse.py::test_ads_off_ships_no_client_id_no_slots`). e2e `phase-9.spec.ts::with ads off, no ad code loads and nothing asks for consent` enumerates every `script[src]` on the landing page and asserts none is `adsbygoogle`/`googlesyndication`, that no banner appears, and that a tool page still works. `/ads.txt` is rendered from `ADSENSE_CLIENT_ID` (nginx proxies the site root to the API), and with no id it says so rather than naming a seller: `::test_ads_txt_is_rendered_from_the_publisher_id`.
- [x] With ads on + consent granted: slots render in the three allowed surfaces only; ceremony/editor/verify provably ad-free. → `ad-slot.spec.ts` (9 tests): nothing renders with ads off, nothing renders before a decision, nothing renders after a decline, nothing renders on a forbidden route, the box is reserved at its declared height *before* the ad arrives, and the provider script is appended exactly once across several slots. The exclusion is code, not convention — `AdSlot.FORBIDDEN = ['/s/', '/verify', '/legal/', '/app/doc']` is asserted, **including the editor/viewer canvas**, and e2e `::with ads on and consent granted, slots appear — and only there` grants consent with ads stubbed on, sees the landing slot, then visits `/verify` and `/legal/privacy` and asserts zero ad markup. Placements: dashboard rail (≥1280px), one inline card in the list below that, tool-completion panel, landing.
- [~] Consent banner appears for EEA-simulated visitors; declining yields non-personalized ads; choice persisted. → **Declining yields *no* ads, not non-personalized ones** — the deliberate deviation recorded in the Decisions log below, because serving NPA correctly under TCF needs the certified CMP's signal and guessing at it is a compliance failure rather than a lost impression. Everything else is ticked: the region rule is one server-side list (`CONSENT_REQUIRED_REGIONS`) tested across nine regions including "no region at all → ask" (`::test_consent_is_required_where_it_is_required`); the client reports its **IANA timezone** rather than its locale (`consent.service.spec.ts` — `en-US` in `Europe/Berlin` must still be `DE`, or most EU visitors would never see the banner); Consent Mode's default is `denied` for every ad signal before any tag can load; and a decline is stored, survives a reload, and **unloads the tag** (`ConsentService.teardown()`), because a consent that cannot be withdrawn is not consent. e2e `::declining is a real answer and loads nothing`.
- [x] Legal pages live, linked, and matching real system behavior (retention numbers cross-checked against beat config in a test). → `/legal/privacy`, `/legal/terms`, `/about` (plus `/legal/esign-disclosure` from Phase 8), prerendered, in `sitemap.xml`, and linked from a shared footer on the landing page, every tool page, the dashboard and the ceremony. - [x] Unverified accounts cannot send sign requests (uploading stays open — guests can upload, so accounts must too); verified flow smooth (<1 min via Mailpit locally). → `test_sign_api.py::test_an_unverified_account_cannot_send_but_can_build` (403 `email_not_verified`, and **no mail sent**) beside `test_ads_and_abuse.py::test_an_unverified_account_can_still_do_everything_else` (upload 201, operation 202). Registration now mails the link — without that the gate was unreachable from a cold start — and the refusal is answered *where it happens*: e2e `::an unverified account is told why it cannot send yet` asserts the inline panel, that the built request is still on screen, and that the resend button gives an honest answer (sent, or the cooldown). `::an account verifies its address through the inbox` does the whole loop through Mailpit in about two seconds.
- [x] Ads render for a guest with consent granted, and the CMP consent flow completes with no account. → The consent path touches no account at all: the banner, the choice and the slots are all driven by `/api/config/` + `localStorage`, and the e2e specs that exercise them run in a cleared context with no registration anywhere in the path. `ad-slot.spec.ts` drives the same code with a guest-principal config payload.
- [x] All throttle/quota limits return the standard error shape with human-readable messaging in the UI. → Every limit raises a `ZenAPIException`, so the §6 shape is structural: `{"error": {code, message, details}}` plus `Retry-After`. Phase 9's matrix, each exercised: `upload` 20/hour per **account** and **only on writes** (`::test_uploading_too_fast_is_refused_with_a_retry_after` asserts the 429 *and* that the library is still readable — the first cut throttled GETs and locked a user out of their own files in twenty page loads); `verify` 10/min per IP behind a 60/hour ceiling (`::test_verification_is_capped_per_hour_as_well_as_per_minute`); `public_sign` 20/min per IP **plus 200/day per token** (`::test_public_signing_is_capped_per_token_as_well_as_per_ip`); `auth` 10/min per IP; and a 120 s per-account cooldown on the verification mail (`::test_the_verification_mail_has_a_cooldown`) — that mail is transactional, so the suppression list cannot stop it and the cooldown is the cap.

**Decisions** (also in the Decisions log):
- **`List-Unsubscribe` points at the API, and the token carries a keyed hash rather than the address.** RFC 8058 one-click is a server-to-server POST with no JavaScript in sight; aimed at an Angular route it returned the app shell, suppressed nothing, and told the person they had unsubscribed. A browser GET now redirects to a page that *asks* — the link is printed in every footer and travels with a forwarded message, so one that fires on load is a kill switch anybody downstream can pull — and the suppression is reversible from that page and from admin.
- **A suppressed invitation is not a notified recipient.** `mail.send` returns a count and every caller honours it: the recipient is left un-notified and the audit event records who was actually reached. An e-signature audit trail that asserts a delivery the suppression list swallowed is the wrong kind of wrong.
- **Declining consent means no ads, not non-personalized ads** (see the criterion above), and outside the consent regions — where nothing is asked — ads *do* load. Gating on an explicit `granted` everywhere would have meant an ad-funded product that never shows one.
- **The abuse report is answered without the reporter's request context.** `record()` stores `client_ip`, and the audit trail is readable by the owner — so the first cut handed the person being reported their reporter's IP address. The report row keeps it for staff. The response also no longer returns the running count: telling each reporter how close they are to pausing somebody's contract is an invitation to organise.
- **Turnstile sits on register and on *completing* a signature**, not on opening a signing link: somebody who was legitimately sent a document should not meet a puzzle before they can read it. Behind `CAPTCHA_ENABLED`, off in dev and test.

**Decisions** (also in the Decisions log):
- **Editing an unlocked document takes its protection off, and says so.** The engine works on decrypted bytes; neither password is recoverable from the other, so the original encryption cannot be put back faithfully, and re-encrypting with the one password we were given would quietly make it both. - **Guessing is throttled per document, not per principal** (5/min): the thing being guessed at belongs to the document, and an attacker with several sessions would otherwise get five tries each. Charged in the worker, where the guess is known to be wrong; refused at the view. `::test_guessing_is_throttled_per_document`.
- **The PII fixture gained a third email address.** The review list only earns its existence if a user can keep some matches and drop others, and two is not enough to show that (the phase's own E2E says "review shows 3, uncheck 1, apply 2").
- **`THROTTLE_AUTH` is relaxed in `config.settings.dev` only.** It is per IP, and in dev the whole e2e suite is one IP; 10/min meant the eleventh test to register an account failed for a reason unrelated to what it tested. Production keeps the real rate.
